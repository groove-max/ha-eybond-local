# EyeBond Local для Home Assistant

Локальний моніторинг і підтримуване керування сонячними інверторами через **Wi-Fi-колектори, сумісні з EyeBond**, зокрема для пристроїв із застосунками **SmartESS, SmartValue та DESSMonitor**.

## Чи підходить інтеграція для мого інвертора?

Важливі **колектор і протокол**, а не лише бренд. Моделі Anenji, PowMr, Sandisolar, MUST, Victor, Kevolt та інших виробників мають різний рівень підтримки. Назва застосунку або спільний ідентифікатор прошивки не гарантують сумісності.

Перегляньте [пояснення сумісності](docs/user/COMPATIBILITY.uk.md) та [каталог моделей із підтвердженнями — англійською](docs/generated/INVERTER_MODEL_CATALOG.generated.md). Модель поза списком може працювати через підтримуваний протокол; для підтвердження нового обладнання потрібен пакет підтримки.

## Що вміє інтеграція

- Читає дані сонячних панелей, батареї, навантаження, мережі, енергії та стану через локальну мережу.
- Надає підтверджені локальні налаштування залежно від моделі, прошивки та режиму керування.
- Знаходить колектори локально або підключає їх через явно налаштовані маршрутизовані мережі.
- Пропонує **Хмара + Home Assistant** і **Лише Home Assistant** для сумісних колекторів.
- Допомагає дослідити відсутні налаштування через **Shadow Learning / Write Controls**, якщо пристрій підтримується.
- Створює пакет підтримки та надає діагностику й захоплення трафіку за вказівкою розробника.
- Працює з додатковою [EyeBond Local Card](https://github.com/groove-max/ha-eybond-local-card).

Для звичайних локальних показань вхід у хмару не потрібен. У режимі «Хмара + Home Assistant» колектор продовжує спілкування з хмарою виробника. Навчання та хмарна діагностика — окремі необов'язкові функції.

## Встановлення

**Спочатку оберіть канал.** Поточна опублікована бета 0.3 — **0.3.0-beta.5**, а GitHub «Latest release» зараз веде на старішу стабільну **0.1.53**. Нові виправлення у `main` не потрапляють автоматично до beta.5. [Версії та безпечне оновлення →](docs/user/INSTALLATION.uk.md)

1. Додайте репозиторій у **HACS → Custom repositories**, категорія **Integration**.
2. Завантажте потрібну опубліковану версію. Для бети за потреби увімкніть показ попередніх релізів у діалозі завантаження.
3. Перезапустіть Home Assistant.
4. Відкрийте **Налаштування → Пристрої та служби → Додати інтеграцію → EyeBond Local**.

Без HACS скористайтеся [ручним встановленням](docs/user/INSTALLATION.uk.md).

### Тестування неопублікованої гілки main

Встановлюйте тестову збірку лише свідомо, зазвичай на прохання розробника. Зробіть резервну копію, замініть повний каталог інтеграції та перезапустіть HA. Не змішуйте версії й не залишайте резервні каталоги в `custom_components`. [Повна інструкція](docs/user/INSTALLATION.uk.md#testing-main).

Cloud Bridge 0.4 розробляється окремо й **не входить до опублікованої бети 0.3 або поточної збірки main 0.3**.

## Налаштування

1. Підключіть колектор до Wi-Fi/LAN, звідки Home Assistant може до нього звернутися.
2. Оберіть правильний мережевий інтерфейс HA та запустіть пошук.
3. Додайте визначений колектор; інвертор визначається після цього.
4. Перевірте живі показання перед зміною налаштувань.

Для іншої підмережі додайте відомі IP колекторів до пошуку або вкажіть адресу зворотного підключення вручну. Broadcast зазвичай не проходить через маршрутизатор. [Перше підключення](docs/user/GETTING_STARTED.uk.md).

## Після налаштування

Зазвичай з'являються окремі пристрої **колектора** та **інвертора**. Почніть із режиму **Авто**. **Лише читання** вимикає запис, а **Повне керування** може відкрити неперевірені налаштування й не підтверджує їхню сумісність.

Спочатку залиште автоматичний інтервал опитування. [Докладно про сенсори й керування — англійською](docs/user/RUNTIME_AND_INVERTER.md).

## Навчання пристрою

Немає налаштування, яке є в хмарному застосунку? **Write Controls** може визначити хмарні команди та додати локально підтверджені контроли для підтримуваних пристроїв. Це не гарантує всі параметри або весь діапазон значень.

Аналіз лише для читання збирає докази й **не додає контроли автоматично**. Активне навчання може перервати хмарне з'єднання та залишити захисне утримання після непідтвердженої команди. Спочатку прочитайте [посібник із навчання та відновлення](docs/user/LEARNING.uk.md).

## Усунення проблем

[Підключення, хмара й недоступні сенсори](docs/user/TROUBLESHOOTING.uk.md) — перевірки без скидання пристрою.

### Відома проблема хмарної телеметрії

У деяких інсталяціях хмарні оновлення зупиняються, хоча показання HA змінюються. Причину та універсальне виправлення ще не підтверджено. Це відрізняється від режиму «Лише Home Assistant» або захисного утримання після навчання. За можливості зберіть діагностику під час збою до перезапуску. [Що перевірити й надіслати](docs/user/TROUBLESHOOTING.uk.md#cloud-updates-stop).
